# CLAUDE.md

Guide for working on **Filester Navigator**, a faster, searchable UI for a [filester.me](https://filester.me)
account. It runs on Cloudflare Workers and talks to Filester's own APIs for the signed-in user.
Live at `fs.snippface.vip`. The roadmap is in [`TODO.md`](TODO.md); keep it up to date (see the end of this file).

## Stack

- **TanStack Start** (React 19, TanStack Router file routes, server functions, server routes) built with **Vite 8**.
- **Cloudflare Workers** through `@cloudflare/vite-plugin`; locally it runs in workerd. Bindings come from
  `import { env } from 'cloudflare:workers'`.
- **TanStack Query** for all Filester data on the client. **Tailwind v4** with tokens in `src/index.css`
  (`@theme`, dark mode through `prefers-color-scheme`, and `@utility` classes such as `btn`, `card`, `chip`, `input`, `th`, `td`).
- **Cloudflare KV** (`STORE` binding) holds only opt-in, encrypted per-user backup settings and daily usage counters.
- **R2 / S3** through `aws4fetch` (SigV4). Each user brings their own bucket.
- Icons from `lucide-react`. No chart library: charts are plain HTML and CSS (see `src/pages/Insights.tsx`).
- Tests: **Vitest** (unit) and **Playwright** (e2e) against a mock Filester and **moto** as the S3 server.

## Commands

```bash
npm run dev          # http://localhost:3000 in workerd (needs .dev.vars, see .dev.vars.example)
npm run typecheck    # tsc --noEmit (covers src and tests)
npm run lint         # eslint
npm test             # vitest unit tests
npm run build        # production build
npm run build:test   # build with tests/e2e/wrangler.test.jsonc + its .dev.vars (points at the mocks)
npm run test:e2e     # playwright; starts the mock Filester, moto and vite preview itself
npm run deploy       # build + wrangler deploy (the owner also uses `bun run deploy`)
```

Before every commit run `typecheck`, `lint`, `test`, and for UI or server changes also `build:test` then `test:e2e`.
CI (`.github/workflows/ci.yml`) runs all of these on every push.

E2E needs `pip install "moto[server]"` (`MOTO_CMD` overrides the command) and a Chromium. To use a browser
Playwright didn't install, set `PW_CHROMIUM_PATH`; in Claude's cloud sandbox that's
`/opt/pw-browsers/chromium-1243/chrome-linux64/chrome`. Never run `playwright install` there. Set `CI=1` to make Playwright start
fresh servers instead of reusing running ones. After changing app code, run `build:test` again: e2e tests the built `dist/`.

## Filester: facts and quirks the code depends on

Full details are in `docs/API.md`. When the real Filester disagrees with these, update the code, `docs/API.md`, the
mock and this list.

- **Browsers can't call Filester** (CORS allows only filester.me), so everything goes through `/api/fs/*`.
  The Worker attaches the user's credentials from the encrypted cookie.
- **Two credentials:** the web session `auth_token` cookie (for `/api/*` on filester.me) and the API key (Bearer, for
  `u1.filester.me/api/v1|v2`). The API key is scraped from `/account` after sign-in; if that fails, the user pastes it.
- **File list:** `GET /api/files/export.csv` is one request, doesn't count against the API key and includes
  last view/download dates. The paginated `v1/files` is only the fallback.
- **Folder `file_count` includes deleted files.** Count files from the real file list (`buildIndex`) and show the
  difference as "N deleted".
- **Deleting a folder doesn't delete its subfolders.** They become orphans, and `manager/data` then returns no
  folders at all. Bulk delete therefore deletes the whole subtree, deepest folders first.
- **`folder/edit` with an empty `password` removes the folder's password.** Always re-send it; Hide-related
  skips password-protected folders.
- **Previews use the view endpoint** (`/v2/api/public/view`): it counts a *view*, never a download. Thumbnails are
  public at `filester.me/t/<uuid>`. The proxy exposes only `view` (`/api/fs/view`), never the download endpoint.
  The lightbox waits 250 ms before requesting one and reuses links per file, so flicking past files doesn't count views.
- **Asking for a download token counts as a download.** Never request one just to probe or check. Download
  stats update a few minutes late.
- **Inactivity deletion:** FAQ says 35 days without downloads, the API docs say 45 days without views or downloads.
  The user picks which rule to use; FAQ is the default.
- **`account/stats`** returns totals, a 30-day series, trending and all-time lists, and a 7×24 heatmap (Sunday first, UTC).
  Folder items in it have no fixed shape, so they are normalized in `getAccountStats`.
- CDN download tokens embed the client IP but aren't enforced. Ranged requests work (backups rely on this).

## Conventions

- **All mutations go through `useActions()`** (`src/state/actions.tsx`): confirm dialog, then progress in the task
  panel for more than one item, then a toast, then cache invalidation. Bulk work runs in batches and can be cancelled.
- **Destructive bulk actions** spell out exactly what will be deleted (counts, subfolders, size) before running.
- **Search boxes bound to the URL** must use `useUrlText` (local text, URL updated after a pause and on blur).
  Binding `value` straight to a search param drops keystrokes; `tests/e2e/typing.spec.ts` guards this.
- **Every new Filester response the app reads** gets a spec in `SHAPES` (`src/lib/shape.ts`), a probe in
  `ConnectionCheck` if it's read-only, and a route in the mock.
- **Per-browser preferences** go in `localStorage` under an `fsnav.` prefix, wrapped in try/catch, and keyed by Filester
  username when they belong to an account (see `src/state/pins.ts`).
- **UI copy:** short, plain sentences that say what happens and why, with no jargon or error codes. Explain Filester's
  oddities to the user where they show up (for example "N deleted (Filester still counts them)").
- **Layout:** works at 375px wide with no horizontal page scroll. Check light and dark mode.
- **Charts:** one measure per chart in the accent colour; magnitude as shade steps; hover or tap readout; a
  screen-reader table. No dual axes.
- Server-only modules end in `.server.ts`. Test-only knobs (`FILESTER_*_ORIGIN`, `FILESTER_CDN_REWRITE`,
  `R2_ENDPOINT_OVERRIDE`, `BACKUP_PART_MB`, `TURNSTILE_VERIFY_URL`) must stay inert in production.

## Security and privacy rules (the privacy note promises these)

`src/components/PrivacyNote.tsx` tells users exactly what is stored. **If a change stores or logs anything new,
update that note in the same commit.**

- Never store passwords, file contents or the file list on the server. The password goes to filester.me once.
- The Filester token and API key live only in the AES-GCM sealed, HttpOnly `__Host-fsnav` cookie (`SESSION_SECRET`).
- R2 keys go in KV, encrypted with a key derived from `CREDENTIALS_SECRET`, with the Filester user id as AAD, and are
  never sent back to the browser (`maskConfig`). One user's backups must never be reachable by another.
- Stored request logs are off (`observability.enabled: false`). Debug with `npx wrangler tail`.
- No analytics or third-party scripts; the only exception is Turnstile when it's enabled.
- The ALLOWED_USERS and Turnstile checks run **before** credentials are sent to Filester.

## Testing rules

- **Never point tests at a real Filester account or a real bucket.** Use `tests/mock/filester-mock.mjs` and moto.
  The mock has control routes: `POST /__reset`, `GET /__state?user=`, `POST /__age {days, names}`,
  `POST /__break {what: 'folders'|'export'|'html'|'stats'|'turnstile'}`.
- **Destructive e2e flows check the mock's state after each step**, so a wrong selection can't cascade (a past
  unfiltered "select all" wiped a real test account).
- Mock user ids are random on every reset, which isolates KV state between tests.
- Specs import `test`/`expect` from `tests/e2e/helpers.ts`. It serves a fake Turnstile script; use
  `fakeTurnstile(context)` for any extra browser context.
- When a bug is reported, first write a test that reproduces it against the old build, then fix it.
- Read-only checks against the real filester.me are fine when needed to confirm a response shape. Never upload,
  delete or request download tokens on a real account from tests.

## Deploy

See `docs/DEPLOY.md`. Workers Builds deploys `main` automatically; the owner sometimes deploys by hand with `bun run deploy`.
- **Secrets:** `SESSION_SECRET`, `CREDENTIALS_SECRET`, plus optional `ALLOWED_USERS` and `TURNSTILE_SECRET`.
- **Vars** in `wrangler.jsonc`: `BACKUP_DAILY_CAP_GB` (50). `TURNSTILE_SITE_KEY` can be a var or a secret. Plain-text vars added in
  the dashboard are overwritten by `wrangler.jsonc` on each deploy, so put them in `wrangler.jsonc`.
- **KV `STORE`:** created automatically on the first deploy (no id in config).
- After a deploy, hard-refresh (Ctrl+Shift+R): the installed PWA can keep the old build until then.

## Git

- Work on `main` (the remote is `new` → `github.com/patelharsh9797/filester-new-ui`). The old Node version lives on branch `node`.
- Commit subjects are imperative ("Add …", "Fix …"), and the body explains what changed and why.
- Never put model names or IDs in the repo. Before committing, scan for secrets: no real passwords, API keys, tokens or
  AKIA keys. `tests/e2e/.dev.vars` is test-only and committed on purpose.
